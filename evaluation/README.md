# 12문항을 어떻게 정했나

책담 관리자가 실제로 조회할 만한 업무에서 출발해, 답을 내려면 어떤 판단이 필요한지에 따라 난이도를 나눴다. 단계마다 네 문항씩 배치해 같은 분모에서 비교한다. 실제 이용자의 검색 로그를 표본 추출한 데이터셋은 아니다.

| 단계 | 선정 기준 | 문항 예시에서 확인할 점 |
| --- | --- | --- |
| Level 1 | 한 테이블에서 값이나 NULL로 필터링 | 분실 소장본은 owned_book.status의 LOST 조건 하나로 찾을 수 있다. |
| Level 2 | 둘 이상의 테이블을 연결하거나 묶음·부재를 계산 | 회원별 현재 대출 수는 회원과 대출을 연결하고, 0권인 회원도 결과에 남겨야 한다. |
| Level 3 | 도서관 업무 용어를 여러 조건으로 해석 | ‘대출 가능’은 정상 소장본이면서 현재 미반납 대출이 없는 상태다. |

### 문항별 평가 의도

| 번호 | 실제 질문 | 확인할 능력 |
| --- | --- | --- |
| L1-01 | 분류가 컴퓨터인 도서의 도서번호, 제목을 도서번호 오름차순으로 보여줘. | 단일 테이블 조건 검색 |
| L1-02 | 정상 이용 상태인 회원의 회원번호, 이름을 회원번호 순서로 보여줘. | 회원 상태 코드 해석 |
| L1-03 | ISBN이 등록되지 않은 도서의 도서번호와 제목을 도서번호 순으로 보여줘. | 선택 입력 NULL 처리 |
| L1-04 | 분실 상태인 소장 도서의 관리번호와 보관위치를 관리번호 순으로 보여줘. | 소장 상태 조건 |
| L2-01 | 미반납 대출의 대출번호, 회원 이름, 도서 제목, 반납예정일을 대출번호 순으로 보여줘. | 네 테이블 JOIN과 미반납 필터 |
| L2-02 | 모든 도서의 도서번호, 제목, 정상 소장 권수를 도서번호 순으로 보여줘. 정상 소장본이 없는 도서는 0권으로 표시해. | LEFT JOIN과 0건 보존 |
| L2-03 | 모든 회원의 회원번호, 이름, 지금 빌린 책 수를 회원번호 순으로 보여줘. 현재 대출이 없는 회원도 0권으로 표시해. | 과거 대출과 현재 대출을 구분한 집계 |
| L2-04 | 대출 이력이 한 번도 없는 회원의 회원번호, 이름을 회원번호 순으로 보여줘. | NOT EXISTS 상관 서브쿼리 |
| L3-01 | 모든 도서의 도서번호, 제목, 지금 대출 가능한 권수를 도서번호 순으로 알려줘. 대출 가능한 책이 없어도 0으로 보여줘. | 정상 상태와 미반납 대출 부재를 동시에 적용 |
| L3-02 | 현재 연체 중인 대출의 대출번호, 회원 이름, 도서 제목, 연체 일수를 대출번호 순으로 보여줘. 오늘이 반납예정일인 책과 이미 반납한 책은 제외해. | 현재 연체의 날짜 경계와 과거 지연 반납 제외 |
| L3-03 | 지금까지 가장 많이 대출된 도서의 도서번호, 제목, 누적 대출 횟수를 보여줘. 공동 1위는 모두 포함하고 도서번호 순으로 정렬해. | 소장본을 도서별 합산하고 공동 순위 보존 |
| L3-04 | 대출 이력은 있지만 현재 빌린 책은 없는 회원의 회원번호, 이름을 회원번호 순으로 보여줘. | 이력 존재와 미반납 부재의 차이 |

[질문 원본과 정답 SQL](questions.json)에서 각 문항의 question, intent, reference_sql, ordered를 확인할 수 있다. 두 프롬프트에 같은 질문을 사용하며 모델에는 정답 SQL과 정답 행을 제공하지 않는다. 질문에 출력 열, 정렬, 동률 처리를 명시한 것은 결과를 같은 기준으로 채점하기 위해서다.

### 평가 절차

샘플 평가 DB와 기준일 2026-11-23을 준비한다. 프로젝트 가상환경에서 아래 명령을 실행한다.

```powershell
python scripts/evaluate_nl2sql.py --reference-only
python scripts/evaluate_nl2sql.py --reference-date 2026-11-23 --output-dir evaluation/results/reproduction
```

첫 명령은 정답만 검증한다. 두 번째 명령은 동일한 MySQL 읽기 전용 스냅샷에서 모델을 총 24회 호출한다. 열의 위치, 값, 중복, 필요한 정렬 순서를 비교한다. 실행된 SQL도 결과가 다르면 오답이며 실패도 12문항 분모에 포함한다.

초기 실측은 [기존 Ollama 결과](results/ollama/llm_comparison.json)에 저장돼 있다. 이번 개선은 이 12문항의 오류를 검토한 뒤 같은 문항에서 다시 측정한 것이다. 처음 보는 질문에서의 정확도는 별도의 미사용 문항으로 측정해야 한다.

### 재평가 결과

| 같은 12문항 | Simple 정답 | Enhanced 정답 |
| --- | --- | --- |
| 최초 평가 | 2/12 | 5/12 |
| 한국어 용어 설명을 교체한 중간 실험 | 3/12 | 3/12 |
| 단일 대상 조회에서 제공할 테이블을 좁힌 최종 실험 | 3/12 | 7/12 |

최종 보강 방식은 Level 1에서 4/4, Level 2에서 2/4, Level 3에서 1/4였다. 최초 평가와 비교하면 Level 1에서 두 건 늘었다. 한 테이블로 풀 수 있다고 판단한 경우 모델에 그 테이블과 열 의미를 주어 불필요한 JOIN을 줄인다. 복합 질문은 기존 전체 스키마와 업무 규칙을 사용한다. 변경한 적이 없는 Simple도 재실행에서 정답 한 건이 달라졌으므로 수치는 각 실행의 관측값으로 해석한다.
