# 요구사항과 SQL 연결

이 문서는 6조 중간 설계의 다섯 테이블과 실제 구현 함수의 연결을 설명한다.
`sql/business_queries.sql`은 발표용 쿼리 예제이며, 웹 요청에서는
`library_app/services.py`의 매개변수 바인딩 쿼리를 실행한다.

| 요구사항 | 구현 함수 | SQL 예제 | 확인할 결과 |
|---|---|---|---|
| F01 도서 등록·수정 | `save_book` | Q07, Q14 | ISBN 중복 차단, ISBN 없는 도서 허용 |
| F02 소장 도서 관리 | `add_owned`, `update_owned` | Q08, Q13 | 개별 관리번호와 상태 관리 |
| F03 도서 검색·조회 | `list_books`, `book_detail` | Q01, Q05 | 분실·폐기 및 대출 중 책을 대출 가능 수량에서 제외 |

## 모델 유지와 확장

- 기존 테이블명과 속성은 `book`, `owned_book`, `member`, `user_account`, `loan`을 유지했다.
- `book`에 `metadata_source`, `source_url`, `imported_at`을 추가해 수동 입력·가상 샘플·외부 API 출처를 구분했다.
- `loan.open_flag`는 미반납이면 1, 반납했으면 NULL인 생성 열이다. `UNIQUE(owned_id,open_flag)`로 미반납 중복만 막고 과거 이력은 여러 건 보존한다.
- 회원과 소장 도서의 PK/FK는 물리적 삭제를 제한한다. 탈퇴·폐기는 상태 변경으로 처리한다.
- `user_account.member_id`는 고유한 선택적 FK이다. 관리자 계정은 NULL, 회원 계정은 반드시 회원을 가리킨다.

## 구현을 위해 정한 정책

중간 설계에는 대출 한도·기간의 숫자가 없으므로 기본값을 `MAX_LOANS=3`,
`LOAN_DAYS=14`로 두었다. `.env`에서 변경할 수 있으며 실제 학교 도서관 정책을
재현한다고 주장하지 않는다. 연체 기준일은 기본적으로 실행일이다. 재현 가능한
평가에서는 `REFERENCE_DATE=YYYY-MM-DD`를 사용한다.

분실·폐기 변경은 미반납 대출이 없는 책에만 허용한다. 과제 범위에 분실 배상·
분실 대출 종결 업무를 추가하지 않았으므로 진행 중인 대출이 있으면 먼저 반납
처리를 완료해야 한다. 탈퇴 회원의 기존 대출 내역은 유지한다.

## 입력과 트랜잭션

- ISBN은 선택 입력이다. 값이 있으면 하이픈을 제거한 13자리 숫자와 검사 숫자를 검증한다.
- 날짜와 필수 문자열을 검증하고 SQL에는 값을 문자열로 이어 붙이지 않는다.
- 대출은 회원 행부터 잠가 같은 회원의 동시 요청이 대출 한도를 우회하지 못하게 한다.
- 이어서 소장 도서를 잠그고 최신 미반납 내역을 확인한다. 같은 책을 두 회원이 동시에 빌려도 하나만 성공한다.
- 반납은 같은 잠금 순서를 사용하며, 오류 발생 시 전체 트랜잭션을 취소한다.
- NL2SQL은 웹 관리 기능과 별도의 SELECT 전용 DB 계정을 사용한다. `user_account`는 조회 허용 대상에서 제외하고, `member.phone`에도 조회 권한을 주지 않는다.

## 샘플 데이터 범위

기본 데이터는 가상 도서 18종, 개별 책 21권, 가상 회원 8명, 대출 이력 14건,
사용자 계정 8개이다. `metadata_source='SAMPLE'`로 표시하며 ISBN은 NULL이다.
공주대학교 소장자료 또는 국립중앙도서관 API 실시간 수집 자료로 표현하지 않는다.
API 키를 설정한 후 가져온 자료는 별도로 등록한다.
