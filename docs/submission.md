# 제출 전에 채울 항목

보고서는 안내서의 순서에 맞춰 서론, 관련 서비스, 시스템 설계, 구현, 평가, 결론, 참고문헌을 수록했습니다. 발표 자료는 PDF 전체 화면으로 발표할 수 있습니다. 코드는 이 프로젝트 폴더를 GitHub에 올려 실행 방법과 파일을 공유합니다.

## 실제 평가를 기록하는 방법

1. 비교 평가용 DB를 `REFERENCE_DATE=2026-11-23`으로 새로 초기화합니다. `README.md`의 평가 재현 절을 따릅니다.
2. `.env`에 도서 API 키를 저장하고 Ollama 모델을 설치합니다. 두 API 화면에서 검색·실행을 각각 검증합니다.
3. `scripts/evaluate_nl2sql.py`를 기본 모드로 한 번 실행합니다. 결과인 `llm_comparison.json`에서 두 방식의 `summary`와 질문별 결과를 읽습니다.
4. 평가 기준일은 2026-11-23이며, 초기 샘플 DB에 `qwen2.5-coder:3b`를 적용했다. 같은 12문항을 방식별로 한 번씩 실행했다.

| 프롬프트 방식 | Level 1 정답 / 4 | Level 2 정답 / 4 | Level 3 정답 / 4 | 전체 정답 / 12 |
| --- | --- | --- | --- | --- |
| 기본 스키마 | 0 | 2 | 0 | 2 (16.7%) |
| 스키마·업무 규칙 보강 | 2 | 2 | 1 | 5 (41.7%) |

예를 들어 분실 도서의 위치를 묻는 L1-04에서 기본 방식은 `status = '분실'`로 검색해 빈 결과를 반환했다. DB에 저장되는 코드가 `LOST`라고 알려준 보강 방식은 실제 분실 도서를 찾았다. 공동 1위를 모두 구하는 L3-03은 두 방식 모두 정답과 일치하지 않았다. [질문별 생성 SQL과 결과](../evaluation/results/ollama/llm_comparison.json)

## 발표 흐름

10~15분 중 설계 설명에 3분, 관리자·회원·도서 API 시연에 4분, 자연어 조회와 평가에 4분, 결론에 1분 정도를 배분합니다. 시연 때 소장본 여러 권, 반납일과 `open_flag`, 당일과 연체의 구분을 각각 데이터로 보여줍니다.
